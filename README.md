# Учебный ассистент

Развёртывание [OpenWebUI](https://github.com/open-webui/open-webui) как школьного
ИИ-ассистента для учителей: интерфейс в стилистике МЭШ, модель OpenAI через
[ProxyAPI](https://proxyapi.ru), урезанные права обычных пользователей и готовые
методические промпты (план урока, объяснения по-разному, рабочий лист).

## Архитектура

```
Браузер ──HTTPS──> Caddy (внешний, порты 80/443)
                     │  docker-сеть "proxy"
                     ▼
                 openwebui:8080  ── api.proxyapi.ru ──> proxyapi-relay:443
                                     (DNS-алиас сети)        │ SSH-туннель
                                                             ▼
                                                   хост в РФ ──> api.proxyapi.ru
```

- **openwebui** — контейнер OpenWebUI. При старте `custom/patch.py` накатывает
  кастомизацию поверх образа (темы, шрифты, иконки, верхняя панель, имя),
  поэтому обновления образа её не стирают.
- **proxyapi-relay** — крошечный alpine-контейнер с autossh. Он занимает в
  docker-сети DNS-имя `api.proxyapi.ru` и туннелирует TCP до хоста в РФ,
  который уже ходит в настоящий ProxyAPI (с зарубежных IP сервис работает
  нестабильно). TLS остаётся сквозным, relay видит только шифрованный трафик.
- **Caddy** в этом репозитории нет — предполагается существующий Caddy на
  хосте/в докере, подключённый к внешней сети `proxy`
  (см. `docs/Caddyfile.example`).

## Развёртывание

Требуется: docker + docker compose, DNS-запись домена на сервер, SSH-доступ к
хосту в РФ для туннеля.

```bash
# 1. Отдельный пользователь и код
useradd -m openwebui && usermod -aG docker openwebui
su - openwebui
git clone <этот-репозиторий> openwebui && cd openwebui

# 2. Секреты
cp .env.example .env
#   OPENAI_API_KEY  — ключ ProxyAPI
#   WEBUI_SECRET_KEY — openssl rand -hex 32
#   RELAY_HOST      — адрес хоста в РФ

# 3. Ключ туннеля
ssh-keygen -t ed25519 -N "" -f relay/id_ed25519 -C proxyapi-relay
# На хосте в РФ добавить в /root/.ssh/authorized_keys строку (ограниченный ключ,
# только проброс до ProxyAPI, без шелла):
#   restrict,port-forwarding,permitopen="api.proxyapi.ru:443" <содержимое id_ed25519.pub>

# 4. Сеть и запуск (сеть общая с Caddy; IPv6 нужен relay-контейнеру)
docker network create --ipv6 proxy   # если ещё нет
docker compose up -d --build

# 5. Caddy: добавить vhost из docs/Caddyfile.example и сделать
#   caddy reload (Caddy должен быть подключён к сети proxy)

# 6. Первый вход: зарегистрируйте аккаунт — он станет администратором.

# 7. Настройка базы (права, модель, промпты, карточки)
docker compose stop openwebui
sudo python3 scripts/configure_db.py
docker compose start openwebui
```

## Что настраивается

**Переменными окружения (compose):** язык по умолчанию `ru-RU`, имя
«Учебный ассистент», базовый URL ProxyAPI, ключи.

**Скриптом `scripts/configure_db.py`** (OpenWebUI хранит это в базе и
игнорирует env после первого старта):

- права обычных пользователей: только чат и свои диалоги — без настроек,
  workspace, заметок, папок, каналов, веб-поиска и генерации картинок;
- модель по умолчанию `gpt-5.6-sol` («GPT-5.6 Sol») с публичным доступом
  и отключёнными native-инструментами (gpt-5.6 не принимает их вместе с
  reasoning на `/v1/chat/completions`);
- шесть карточек-подсказок на стартовом экране;
- общие промпты: `/план-урока`, `/объяснить-по-разному`, `/учебное-задание`
  (вызываются в чате через `/`).

**Патчем `custom/patch.py` при каждом старте контейнера:** внедрение тем и
шрифтов, фирменные иконки, верхняя панель с кнопкой «Выйти», скрытие меню
пользователя, приветствие с датой и именем, `lang="ru"`, снятие суффикса
«(Open WebUI)», опросы-конструкторы.

## Опросы-конструкторы

На стартовом экране под приветствием — кнопки «План урока»,
«Объяснить по-разному» и «Рабочий лист». Каждая открывает пошаговый опрос в
стиле МЭШ (класс, предмет, тема — кнопками и полями, с тумблерами и
пожеланиями). «Сгенерировать материалы» подставляет ответы во входные данные
соответствующего методического промпта (текст берётся из базы через
`/api/v1/prompts/list`, при недоступности — короткий встроенный fallback)
и сразу отправляет запрос в чат.

## Темы A/B

- **A (по умолчанию)** — стиль справки МЭШ: бирюзовый акцент, Golos Text.
- **B «Классная доска»** — тёмно-зелёная шапка-доска с меловым подчёркиванием,
  PT Sans/PT Serif, бумажный фон.

Переключение: открыть сайт с `?design=b` или `?design=a` — выбор запоминается
в браузере.

## Известные грабли

- **PersistentConfig**: почти все настройки OpenWebUI копируются в базу при
  первом старте, после чего переменные окружения игнорируются. Менять — через
  админку или `configure_db.py`. Исключение: `DEFAULT_LOCALE` и `WEBUI_NAME`
  читаются только из env.
- **WEBUI_SECRET_KEY** обязателен в `.env`: без него ключ генерируется внутри
  контейнера, и каждое пересоздание разлогинивает всех пользователей.
- **Видимость модели**: если у модели есть запись в таблице `model`, обычные
  пользователи видят её только при наличии `access_grant`
  (`principal_type='user'`, `principal_id='*'`). Скрипт это делает сам.
- **Статика**: `/static` отдаётся из `/app/backend/open_webui/static`;
  `patch.py` копирует кастомные файлы в обе статики (build и backend).
- **HTTP/3**: у Caddy анонс h3 должен быть выключен, если не проброшен
  443/udp — иначе браузеры получают обрывы соединения
  (см. `docs/Caddyfile.example`).
- **Обновление custom/**: `patch.py` не трогает уже пропатченный `index.html`
  (маркеры `mes-topbar`/`mes-wizard`), поэтому после изменения скриптов нужен
  `docker compose up -d --force-recreate openwebui` — контейнер получит чистый
  `index.html` из образа и патч накатится заново.
